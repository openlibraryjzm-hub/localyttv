# AppPage (App Configuration)

AppPage is the primary configuration interface for the application header. It has been optimized for **Android/Mobile ergonomics** while maintaining a powerful side-by-side workflow on desktop.

**Related Documentation:**
- **App Banner**: See `app-banner.md` for technical details on the banner system.
- **State Management**: See `configStore.js` for property definitions.
- **Explorer Hubs**: See `explorer-hub-isolation.md` for playlist filtering logic.

---

## 1: User-Perspective Description

- **Mobile-Optimized Structure**:
  - **Headerless Layout**: The bulky top header has been removed to maximize vertical space for configuration controls.
  - **Side-Switcher (Mobile)**: On small screens, a segmented toggle allows users to switch between the **Left Half** and **Right Half** configurations. Only one bar is shown at a time to save space.
  - **Responsive Scaling**: All paddings, margins, and font sizes dynamically shrink on mobile devices to prevent "over-sized" UI elements.

- **The Configuration Bars**:
  - **Left Half Bar**: Controls the banner for the left 50% of the app header.
  - **Right Half Bar**: Controls the banner for the right 50% of the app header.
  - **Live Preview**: Edits are reflected instantly on the main application header while the page is open.
  - **Dual-Mode Workflow**: 
    - **Desktop**: Both bars are displayed side-by-side for rapid symmetrical editing.
    - **Mobile**: Bars are stacked/switchable to ensure usability on vertical screens.

- **Bar Controls**:
  - **Image Upload**: Drag-and-drop or select an image for the specific half.
  - **Copy to Other**: Clones all settings (including the image) from the current bar to the opposite bar.
  - **Scale Slider**: Adjusts image size relative to the 50vw section.
  - **Vertical/Horizontal Offsets**: Precise positioning for alignment.
  - **Motion Scroll Toggle**: Enables/disables infinite horizontal panning.
  - **Flip Image Toggle**: Horizontally mirrors the image for symmetrical designs.

- **The Action Area (Bottom/Scrollable)**:
  - **Flow-Based Actions**: The "Target Playlists" dropdown and "Save" button are located at the very bottom of the scroll area. They only appear after you've scrolled past the configuration boxes.
  - **Target Playlists Dropdown**: A "Target Playlists" dropdown that only shows playlists belonging to the current Explorer Hub. The menu opens upwards to avoid screen clipping.
  - **Compact Save Action**: A square icon button that captures both halves into a playlist-linked preset.

- **Preset Management**:
  - **Unified Presets**: Saving a preset captures the configuration of **both** halves.
  - **Playlist Linking**: Use the dropdown to select which playlists should trigger this banner look automatically.
  - **Explorer Isolation**: The dropdown is filtered so you don't accidentally link a banner to a playlist in a different isolation hub.

## 2: File Manifest

**UI/Components:**
- `src/components/AppPage.jsx`: The core editor component.
- `src/components/BottomNavigation.jsx`: Legacy navigation (not used in this context).

**State Management:**
- `src/store/configStore.js`:
  - `fullscreenBanner` (Left Half)
  - `splitscreenBanner` (Right Half)
  - `stashBanners` / `restoreBanners`: Manages the temporary live-preview state.
- `src/store/playlistGroupStore.js`:
  - `activePage`: Used to filter the Target Playlists dropdown.

## 3: The Logic & State Chain

**Live Preview Logic:**
1. On **Mount**: The editor calls `stashBanners()` to save the current global state.
2. During **Editing**: `updateFullscreenBanner` and `updateSplitscreenBanner` are called. `LayoutShell` detects the existence of the stash and prioritizes these live values.
3. On **Unmount**: The editor calls `restoreBanners()`, which replaces the store's current values with the original stashed ones.

**Side-Switching Logic (Mobile):**
- A local `activeSide` state tracks which half to display on screens below the `lg` breakpoint.
- CSS `hidden` vs `flex` classes are toggled based on this state to ensure a lightweight and non-jumping transition.

**Sync / Copy Logic:**
- The `handleCopy` function takes the source config object and spreads it into the target half's update action. This allows for rapid symmetrical setup.

**Target Playlist Filtering**:
- The "Target Playlists" list is generated by filtering the global `allPlaylists` list against the `activePage` of the explorer hub. 
- **Page 1**: Shows playlists in Page 1 groups + Unsorted playlists.
- **Page 2+**: Shows only playlists assigned to the current hub's carousels.

## 4: Removed Legacy Features

The following features have been removed to radically simplify the experience:
- **Theme Selection**: Legacy "Cool Blue" and "Midnight" advertisements are gone.
- **Player Borders**: Border pattern and width settings have been removed.
- **Player Layout**: Compact mode and spacing toggles have been removed.
- **Interactive SVG Masking**: The crop modal and point-in-polygon hitbox logic have been retired.
- **Spill-Over Logic**: Banners are now strictly contained within the 200px header area.
- **Bulky Top Header**: The fixed back navigation and horizontal action bar have been removed for mobile verticality.
